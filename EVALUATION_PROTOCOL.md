## 6. Repeatability & anti-contamination (frozen)

- Freeze gate (§13) must pass before run 1. No trial on a dirty tree; no fixture edit; checksums re-verified.
- One rep per arm per task (16 runs total). Rationale: 8-category breadth at N=1 is calibration-grade; every comparative sentence carries the N-small caveat (§8). This protocol does NOT claim significance.
- Fresh session per run (D4: fresh session per half, same workdir). Full state reset between runs (per-run state copies; fresh worktrees/scratch dirs).
- ON never contaminates OFF: separate workdirs/worktrees, separate state copies, no shared memory writes; ON `remember/record_memory` writes go to per-run state copies only (live repo JSON never written by trials — verify via `git status` + frozen-copy sha after the program).
- OFF never contaminates ON: OFF has no CodeBro access; `ainotebook` use by either arm is logged, never forbidden.
- Raw evidence preserved per run (§3 layout): JSON session logs (tool USE + RESULTS), prompts, env.json, meta.txt, on.jsonc (ON), work-grade/, grade logs, workdir.diff, verdict.json. D1/D3/D4 grading adds `grade-d1d3d4.log` with the deterministic checks (§5). Real-repo worktrees: `git worktree` from the freeze hash into `/tmp/opencode/dogfood/<run-id>/work`; worktree removed after `workdir.diff` captured; freeze-hash recorded in `env.json`.
- Retry: max 2, infra-only (toolset-fetch failure, 570 s cap hit mid-run, host outage). Model-behavior failures are verdicts, never retries. Judge = operator + deterministic graders; manual spot-checks; committed logs.

## 8. Metrics (frozen — recorded per run in `verdict.json` + aggregate sheet)

Minimum per run: task success/failure (§5 criteria); correctness (grader output); tests passed (visible + hidden counts); regressions introduced (visible green→red, enshrining tests added); time to completion (from `meta.txt`); unnecessary exploration steps (tool-use count before first decisive action, JSON-logged); repeated context/re-explanation (D4-B re-reads; D8 re-derivations); wrong-repository/context events (decoy touched, stale doc followed, historical count cited, adjacent-project file cited); recovery from failure (edits after first red); tool calls where observable (per-tool counts from JSON `tool_use` parts, CodeBro and non-CodeBro); final diff quality (trap-hit class + reviewer note); whether the agent actually consumed CodeBro context (RESULTS inspected, not calls alone — conversion analysis); whether CodeBro output was useful or noise (quote the decisive lines).

Separated in the report:

- **A. Objective engineering outcome:** success, correctness, tests, regressions, diff quality.
- **B. Agent efficiency:** time, exploration steps, repeated context, tool-call counts.
- **C. Context quality:** wrong-context events, recovery behavior, read paths (what doc/memory won and why).
- **D. CodeBro-specific contribution:** consumption proof (tool RESULT → decision link with log quote), decision-changing retrievals, skill-nudge/approval/summary use, noise/cost (irrelevant retrievals, latency, confusion), and explicit no-difference cases.

No subjective impression becomes a score. The only preregistered derived judgments are the binary SUCCESS/FAILURE per §5 and the trap-hit classes per task. Everything else is raw counts + quotes.

## 9. Aggregation rule (FROZEN — the judge may not move these goalposts)

Primary: per-task ON vs OFF SUCCESS counts (grade green + probe pass), reported as raw wins/ties/losses with the N=1-per-arm caveat in every sentence. No p-values. No invented significance. No manufactured score.

- **CodeBro improvement (scope: these task classes only)** iff ALL of: (a) ON success count exceeds OFF by ≥3 across the 8 tasks, AND (b) ≥2 ON successes carry decision-changing-retrieval evidence (tool RESULT quoted in the log demonstrably overturning the fixture-local default), AND (c) no task shows ON harm (ON failure where OFF succeeded AND the log shows CodeBro content causing the failure).
- **Mixed / no aggregate winner:** any other split (including 5-3 without (b), or any ON-harm case offsetting gains) → report per-task, headline `NO AGGREGATE WINNER`.
- **Prior-evidence handling:** pooled Phase-1b T5 (ON 4/5 vs OFF 1/5) is cited as prior context, never merged into this protocol's 16 runs.
